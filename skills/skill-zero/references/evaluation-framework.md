# Skill-Zero 评估框架

用于系统性地评判 R9 工作台中任意 skill 的优劣势，输出可执行的改进建议。

## 评估维度

每个维度按 1–5 分打分，5 分为最佳。

### 1. 触发设计（Trigger Design）
- 触发词是否覆盖了用户可能的真实表达方式
- description 是否能被路由准确识别
- 是否容易与其他 skill 混淆或漏触发

### 2. 功能价值（Functional Value）
- 解决的问题是否明确、具体
- 在 R9 体系内是否具有独特价值
- 是否存在可被其他 skill 替代或合并的冗余

### 3. 内容质量（Content Quality）
- SKILL.md 指令是否清晰、可执行
- 示例是否充分且贴近真实场景
- 是否提供了足够的判断标准和边界条件

### 4. 结构规范（Structure & Compliance）
- 是否符合 skill-creator 的目录与 frontmatter 规范
- 是否遵循渐进式披露原则（metadata → body → references）
- 是否避免不必要的冗余文档

### 5. 依赖与可维护性（Dependencies & Maintainability）
- 外部依赖是否最小化
- 脚本是否经过测试
- 更新成本是否可控

### 6. 体系协同（Ecosystem Fit）
- 与上下游 skill 的衔接是否自然
- 是否明确引用了 china-market-data、r9-rag-engine 等基础设施 skill
- 是否避免了能力重复或真空

## 评估输出格式

对每一个被评估的 skill，输出以下结构：

```markdown
# Skill-Zero 评估报告：{skill-name}

## 总体评分
| 维度 | 得分 | 权重 | 加权得分 |
|------|------|------|----------|
| 触发设计 | x/5 | 20% | ... |
| 功能价值 | x/5 | 25% | ... |
| 内容质量 | x/5 | 25% | ... |
| 结构规范 | x/5 | 15% | ... |
| 依赖与可维护性 | x/5 | 10% | ... |
| 体系协同 | x/5 | 5% | ... |
| **总分** | — | — | **x/5** |

## 优势（Strengths）
- ...

## 劣势（Weaknesses）
- ...

## 机会（Opportunities）
- ...

## 风险（Risks）
- ...

## 优先级改进清单
1. 【高】...
2. 【中】...
3. 【低】...
```

## 评分口径

- **5 分**：行业标杆，几乎无需改动
- **4 分**：优秀，仅有细微优化空间
- **3 分**：合格，存在可感知的改进点
- **2 分**：勉强可用，需要明显改进
- **1 分**：存在结构性缺陷，建议重构或下线

## 评估原则

- 基于 SKILL.md 和实际目录内容进行判断，不依赖假设
- 评估应具体、可执行，避免空泛评价
- 优劣势必须与 R9 工作台整体目标相关
- 改进建议按影响和实施成本排序
